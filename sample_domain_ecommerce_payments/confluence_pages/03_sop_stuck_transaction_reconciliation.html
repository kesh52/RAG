Standard Operating Procedure: Financial Reconciliation & Settlement Replay
SOP Code: SOP-FIN-2026-08
Applicability: Operations, Tier 2 Support, Payments Engineering
Effective Date: 2026-08-30

SOP Purpose

This SOP details the standard operating procedure for handling ledger imbalances, stuck transactions in PENDING_CAPTURE or AUTHORIZED_UNCLAIMED status, and replaying dead-letter settlement queues.

1. Daily Reconciliation Criteria

Reconciliation runs automatically at 04:00 UTC comparing external gateway ledger files (Stripe Settlement Reports, Adyen Day-End Settlement) with internal Postgres ledger_transactions table.

Incident Trigger Thresholds:

  • Variance Threshold: Any total absolute difference > $50.00 USD generates a P2 Alert.
  • Unsettled Orders: More than 10 orders in PENDING_CAPTURE older than 6 hours triggers on-call escalation.

2. Diagnostic Checklist

  1. Query Unreconciled Records: 
    SELECT order_id, gateway_reference, amount, currency, status, created_at
FROM ledger_transactions
WHERE reconciliation_status = 'MISMATCH' AND date(created_at) = CURRENT_DATE - 1;
  2. Classify the Mismatch Reason:
    • STATUS_DESYNC: Gateway recorded captured, internal DB shows pending (lost webhook).
    • AMOUNT_ROUNDING_ERROR: Multi-currency conversion precision mismatch (e.g. JPY or EUR sub-cent rounding).
    • FEE_DEDUCTION_UNTRACKED: Payment processor interchange fee not accounted in net ledger entry.

3. Step-by-Step Remediation Procedure

Scenario A: Lost Webhooks & Status Desync

When the gateway successfully charged the customer but the internal order remained in PENDING_CAPTURE:

  1. Run the automated ledger auto-healer script in dry-run mode: 
    python -m services.reconciliation.sync_tool --mode dry-run --date 2026-08-30
  2. Review the dry-run output log at /var/log/payments/reconciliation_dry_run.log.
  3. Execute live settlement sync: 
    python -m services.reconciliation.sync_tool --mode live --date 2026-08-30 --confirm-ledger-patch
  4. Trigger asynchronous invoice generation for updated orders: 
    curl -X POST https://api.internal.shop/v1/invoices/batch-generate -H "Authorization: Bearer $FIN_SERVICE_TOKEN" -d '{"date": "2026-08-30"}'

Scenario B: Multi-Currency Rounding Mismatch

If discrepancy is under $0.05 per order due to floating-point truncation:

  1. Route discrepancy to the Currency Rounding Expense account (Account ID: ACCNT-9902-ROUNDING).
  2. Mark reconciliation state as AUTO_ROUNDED_RESOLVED.

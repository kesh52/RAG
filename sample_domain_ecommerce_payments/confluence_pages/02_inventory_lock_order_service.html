Inventory Lock Service Overview

This technical guide documents the distributed lock architecture for SKU inventory reservations, deadlocks handling, and Postgres row lock timeout errors during flash-sale traffic spikes.

1. Distributed Locking Strategy

To prevent overselling stock across distributed worker pods, the Inventory Service uses a two-tier locking strategy:

  1. Tier 1: Redis Redlock (Fast-path): Acquires distributed lock on key lock:sku:{sku_id} with a 3000ms TTL.
  2. Tier 2: PostgreSQL Row-Level Lock (Persistence): Executes SELECT available_qty FROM inventory_items WHERE sku_id = :sku_id FOR UPDATE NOWAIT.

2. Error Directory & Thresholds

Error Identifier Trigger Mechanism Impact Primary Root Cause
ERR_STOCK_LOCK_TIMEOUT_504 Worker failed to acquire Redis Redlock within 3000ms. User checkout aborted with "Item currently held by another buyer". Flash sale traffic congestion causing key contention, or Redis Sentinel replica lag.
ERR_POSTGRES_LOCK_NOWAIT_55P03 Postgres query aborted due to lock acquisition conflict (SQLState 55P03). Database transaction rollback on order placement. Concurrent batch replenishment import holding exclusive row locks on popular SKUs during checkout peaks.
ERR_INVENTORY_NEGATIVE_BUFFER Stock count fell below zero after async reconciliation. Physical warehouse fulfillment shortfall. Duplicate capture events or missing idempotency verification on returns processing.

3. Remediation & Recovery Workflow

3.1 Resolving ERR_STOCK_LOCK_TIMEOUT_504 & Redis Congestion

  1. Inspect Lock Contention Metrics: Check active lock keys in Redis cluster: 
    redis-cli -h redis-cluster.internal -p 6379 eval "return #redis.call('keys', 'lock:sku:*')" 0
  2. Flush Orphaned Locks: If locks are held with no active worker PID, run the orphan lock purger: 
    python -m services.inventory.cli purge-orphaned-locks --older-than-seconds 30
  3. Enable Dynamic Backoff Jitter: Apply dynamic jitter configuration to distribute lock retry spikes: 
    kubectl set env deployment/inventory-service REDIS_LOCK_RETRY_JITTER_MS=250 -n fulfillment

3.2 Resolving ERR_POSTGRES_LOCK_NOWAIT_55P03

  1. Kill blocking long-running ETL transactions: 
    SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE query ILIKE '%inventory_replenishment%' AND state = 'active' AND now() - query_start > interval '30 seconds';
  2. Reschedule warehouse bulk imports to off-peak hours (02:00 AM - 05:00 AM UTC).

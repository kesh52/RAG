Payment Gateway Overview

This runbook outlines the operational architecture, error code catalog, and remediation procedures for the Checkout Payment Gateway Service integrating Stripe, Adyen, and PayPal.

1. Core Architecture & Lifecycle

The Payment Gateway Service manages two-phase commit transactions for all customer checkouts:

  1. Authorize Phase: Holds funds against the customer payment method and receives a temporary payment_intent_token (TTL: 15 minutes).
  2. Capture Phase: Executed upon order validation and warehouse inventory reservation confirmation.
  3. Webhook Callback: Asynchronous notification from payment providers delivering final settlement confirmation (charge.succeeded, payment_intent.payment_failed).

2. Error Code Catalog & Root Causes

Error Code Severity Trigger Condition Root Cause
ERR_PAYMENT_304_AUTH_EXPIRED CRITICAL Payment Intent token expired before capture call completed (> 15 mins). Worker queue latency or downstream inventory locking delay caused capture to be delayed beyond token TTL.
ERR_GATEWAY_502_TIMEOUT HIGH Upstream payment provider did not respond within 5000ms. Provider API degradation or egress network firewall packet drop.
ERR_IDEMPOTENCY_COLLISION MEDIUM Duplicate request with identical Idempotency-Key header within 60s. Aggressive client-side UI double-click or network retry loop without backoff.
ERR_WEBHOOK_SIGNATURE_MISMATCH CRITICAL HMAC-SHA256 signature verification failed on incoming provider webhook. Webhook signing secret was rotated in provider dashboard but not updated in HashiCorp Vault / Kubernetes secret.

3. Remediation & Troubleshooting Procedures

3.1 Remediation for ERR_PAYMENT_304_AUTH_EXPIRED

Customer Impact Warning

Orders failing with ERR_PAYMENT_304_AUTH_EXPIRED must NOT be re-authorized automatically without verifying that the customer was not double-charged on their bank statement.

Standard Recovery Steps:

  1. Verify Payment Intent Status: Execute the gateway verification CLI: 
    python -m services.payments.cli verify-intent --intent-id <INTENT_ID>
  2. Release Stuck Inventory: If status is canceled_expired, call the inventory unreserve endpoint: 
    curl -X POST https://api.internal.shop/v1/inventory/unreserve -d '{"order_id": "<ORDER_ID>"}'
  3. Send Customer Notification: Trigger the payment recovery email template TPL_PAYMENT_SESSION_EXPIRED prompting the customer to refresh their checkout session.
  4. Drain and Rebalance Worker Queue: Scale payment worker pods to clear delayed message lag: 
    kubectl scale deployment/payment-worker --replicas=8 -n payments

3.2 Remediation for ERR_WEBHOOK_SIGNATURE_MISMATCH

  1. Retrieve the latest signing secret from the Stripe/Adyen dashboard.
  2. Update secret in Vault: 
    vault kv put secret/payments/webhook_secret STRIPE_SECRET="whsec_live_..."
  3. Restart the webhook ingress pods: 
    kubectl rollout restart deployment/payment-webhook-ingress -n payments
  4. Replay dropped events from the provider dashboard event replay queue.
